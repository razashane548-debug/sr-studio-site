Back up and restore Reshu metadata

For current Reshu v0.3.13-r8 (version code 15). Steps and English button names were checked against the exact release source, not through a fresh device test. This is not a fresh device test; Android file-picker names depend on your phone and provider.

Before starting

This feature saves library names/references, positions, snippets, bookmarks, text notes and highlights. It does not save original book files or audio, and is not a full-phone backup. Keep separate copies of your books. Anyone with both the backup and recovery key can read the saved metadata.

Set up encrypted weekly backup

  1. Open Reshu Settings and select "Encrypted library backup".
  2. Select "Choose account and backup folder". In Android's system picker choose the correct account and a visible backup folder, such as Reshu Backups. Weekly backup needs a provider that supports folder selection and persistent access. Its weekly schedule is inexact, not a guaranteed clock time.
  3. When asked to save the recovery key, choose this device's Documents location, outside the backup folder. The suggested filename is Reshu-recovery-key.rskey. The public build requires primary device storage rather than Drive, and rejects a key inside the backup folder. Follow its instruction to choose device Documents.
  4. When asked "Select the recovery key file you just saved", select that same saved file. Do not choose a key from another backup setup.
  5. Wait for "First encrypted backup verified with the provider. Weekly backups enabled." If an error appears, do not assume setup succeeded.
  6. Keep another safe copy of the recovery key somewhere separate from the phone and backup folder. Never send it to support. Check that your cloud provider has actually synced the backup; provider verification does not prove cloud sync finished.

Make a backup now

  1. In "Encrypted library backup", select "Back up now" after setup.
  2. Wait for "Encrypted backup verified with the provider. Cloud syncing may still be pending."
  3. Check the chosen folder for a Reshu-library-...rsbackup file and confirm sync in your provider before relying on it.

Restore an encrypted backup

  1. Keep a copy of your current book files and metadata before replacing positions.
  2. Open "Encrypted library backup" and select "Restore encrypted backup".
  3. Select the .rsbackup file. When asked, select its matching recovery-key file.
  4. Read the confirmation: matching entries replace current positions; book files and access permissions are not restored. Continue only if that is what you intend.
  5. Wait for "Library restored. Import books again if their access is unavailable." On a new phone, open/import your original books again if needed.

If the recovery key is lost

  1. Do not uninstall, clear app storage, factory-reset or replace the phone while checking what remains.
  2. Look for the saved Reshu-recovery-key.rskey in device Documents and any separate safe copy you made. It must match that backup.
  3. The existing device key may still support scheduled/manual backups, but the public restore flow asks for the matching recovery-key file. Do not assume a device key can be exported as a replacement.
  4. If both the recovery key and device key are lost, this encrypted backup cannot be restored. Support cannot bypass the encryption. Original book files stored elsewhere may still be usable.

Turn weekly backup off

Select "Turn off weekly backup". Existing files remain; this is not deletion. Keep your recovery key for any backup you retain.

Re-linking books

A Re-link action is also available. Restore does not restore original book files or Android access permissions; re-import or re-link your original books when needed.

Other backup buttons

Settings also has "Back up library and bookmarks" and "Restore library and bookmarks", using a reshu-backup.json file. Those are distinct from encrypted .rsbackup files. Do not treat the JSON export as encrypted or interchange the formats.
